## 1 · 结论

**项目处于「P1 内核过半、商业链为零」的状态。**

技术链走得又快又扎实：API 内核 18/128 个 operation（账户 10 / UniProxy 5 / 订阅 2 / healthz 1）
带 155 个顶层测试用例部署到 Cloud Run 并通过云端验证；41 张表的 schema 已上真实 Cloud SQL
（版本 12）；节点建机脚本 5,571 行全部备好且全带 DRY_RUN。

但通往「内部用户付费」的每一环都还没有起步或没有闭环：

| 环节 | 状态 |
|---|---|
| 域名 | **0 个注册**（P1 硬前置：Hysteria2 的 LE 证书走 DNS-01） |
| 自有节点 `bp-node-*` | **0 台**（现在跑流量的是两台旧自用节点，全 Premium 层级） |
| 定价 | 三档套餐**价格与流量数字全部留空** |
| 支付 | 网关**未选型**（EPUSDT vs OxaPay 两派推荐未合并） |
| 邮件 | ESP 未选型，**发信未接通**（`api/internal/handler/auth.go:1140` 的 TODO(P1)，验证码发不出去） |
| 前端 | 双 SPA 是自我声明的「可导航空壳」，无登录态守卫，**测试一行都没有** |

三个最紧迫的发现：

1. 🔴 **生产与 master 漂移。** 生产环境跑的是未合并 PR 栈（#8 → #9 → #10）上的代码；
   master 停留在 6/128 的脚手架，且 master 的 `infra/deploy/deploy-api.sh` 缺
   `BP_ALLOWED_ORIGINS`——`--set-env-vars` 是全量替换语义，**用 master 部署会把生产回滚成
   空壳并静默删掉该线上环境变量**（该隐患已在 #9 内修复但未合并）。
   附带：[ADR 0001](../05-adr/0001-cloudflare-tos-risk.md) 已于 **2026-08-17 获用户批准**，
   但批准记录只在分支上，master 的 [05-adr/README.md](../05-adr/README.md) 仍写「提案，未批准」。
2. 🔴 **成本结构性倒挂。** 上线前两台旧节点已烧 **2,927 GiB / $294.12**（$0.1005/GiB，
   Premium 混合价，2026-06-28 → 08-20），竞品零售约 $0.042/GB——按竞品价卖每 GB 净亏约
   $0.06。内部定价必须走成本加成，而定价的直接前置是 **SKU 级账单拆分**（BigQuery 查询即可）
   与 Premium vs Standard 的显式取舍（成本侧已定量 2.09×，性能侧零数据）。
3. 🔴 **P1 节点侧完全未动。** `bp-node-hk1` 建机 + 装机 + 72 小时验证一步没走，卡在域名。
   roadmap §8.3 明确：不必等完整域名策略，先注册一个可用的。

## 4 · 单位经济（内部付费的账）

「内部用户也付费」的定位是成本分摊与可持续（[product-brief](product-brief.md)），但这笔账目前算不出来：

| 数字 | 值 | 出处 / 含义 |
|---|---|---|
| 实测混合出口成本（Premium） | **$0.1005/GiB** | as-built §10.3；产品化后流量向大陆倾斜，「只会往 $0.23 那一端走」 |
| 竞品零售价 | $0.042/GB | 按竞品价卖每 GB 净亏约 $0.06 —— **内部定价不能对标竞品** |
| Premium → 中国目录价 | $0.23/GiB | 无免费额度；100 GB/人/月 = **$23/人/月**，任何规模 |
| Standard 目录价 | $0.11/GiB | + 200 GiB/源区域/月免费；建模 10 人 $8.80、50 人 $10.56/人/月。**性能零数据**，且实测 Premium 混合价已低于 Standard 目录价——「切了一定更便宜」目前不成立 |
| 固定成本粗估 | $47–55/月 | roadmap §11-R6（两项待核实） |
| TRC20 单笔手续费 | $2.13–4.31 | 对 ¥30–90 月付是 20–85% 侵蚀 → 必须主推年付 → 年付 75 折把退款风险前置 → **退款政策是上线前置** |

**定价定稿的两个直接前置**：① $294.12 的 SKU 级拆分（[pricing §7](../03-product/pricing-and-plans.md)
原话：最接近定价前置条件的一条，今天就能做）；② Premium vs Standard 取舍（`nettier-ab-*` 实测是前置）。

## 9 · 风险要点

三条「缓解措施本身不成立」的风险（roadmap §12 代价第 5 条自标）：
① 域名被封「≤ 30 分钟恢复」零机制支撑，只有域名池常备「已注册已配证书未启用」备件才可能成立；
② budget 告警建不了（B32）；③ 单人运维缓解是「接受」，且 IAP 依赖 Google 身份——
**服务故障时身处大陆的运维自己也进不了后台**，必须备好不依赖本服务的出网路径。

另四条本次审查着重标出：

1. **部署漂移**（§1 第 1 条）——合并 PR 即消除，是唯一一条「零成本消除」的高危项。
2. **切换类应对的共同天花板**：节点侧 60 秒能改配置，但用户手里的订阅刷新是 24 小时或手动——
   协议/域名切换都靠邮件广播推动，而邮件送达率零数据且发信未接通。
3. **成本倒挂**（§4）：必须在「切 Standard（性能未知）」与「成本加成定价（价格偏高）」之间
   做一次显式取舍。
4. **v2node 401 行为未验证**（B7）：现象与 IP 封锁高度相似，会把排障带偏。
