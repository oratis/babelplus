## 1 · 一句话定位

**babel.plus 是一个内部使用的流量中转服务：让中国境内用户经由 Cloudflare 边缘 + Google Cloud
出口，稳定访问全球网络与服务；配套完整的账户、订阅、计费、后台与工单体系。**

「内部使用」是本项目最重要的定语，它同时约束了增长策略与合规姿态（见 §4）。

## 3 · 目标用户与场景

主用户是**已知的、可控范围内的自己人**（内部成员及其邀请的人），而非公开市场的匿名用户。

典型场景，按优先级：

1. **AI 服务访问** — Claude / OpenAI / Gemini / Perplexity 等。Proxy_Skill 的分流规则里
   `🤖 AI` 组就是第一优先级分类，这是最真实的需求信号。
2. **开发与技术工作** — GitHub、包管理源、云控制台、文档站。
3. **一般全球网络访问** — 搜索、社交、新闻。
4. **流媒体** — 优先级最低。Proxy_Skill 已记录：**GCP IP 段普遍被主流流媒体平台封禁**，
   其规则表刻意让流媒体走直连。这是我们相对 conyss（主打「流媒体解锁」）的**结构性劣势**，
   必须在产品文案里诚实说明，不能承诺做不到的事。

> ⚠️ 这一条要写进套餐页：**babel.plus 不承诺流媒体解锁。**
> 用 GCP 做出口就意味着这个能力缺失。若后续要补，必须引入非 GCP 的住宅/商宽出口，属于新的裁决。

---

## 4 · 「内部使用」的三条含义

1. **注册必须受控** — 邀请码制，不开放公开注册。这既是产品定位，也是风控与合规的第一道闸。
2. **规模有上限** — 不追求用户增长曲线，追求**单用户体验质量**与**运维可控性**。
   架构选型上，凡是「为百万用户设计」的复杂度一律不引入。
3. **收款体系服务于成本分摊与可持续，而非利润最大化** — 但账要算清楚：
   出口流量是唯一的真实变动成本，计费模型必须能覆盖它。

## 5 · 范围（做）

| 模块 | 核心能力 |
|---|---|
| **账户体系** | 邀请码注册、邮箱登录、订阅 token、设备数限制、订阅重置、用量可视化 |
| **订阅与流量** | 套餐配额、周期重置、流量包、多格式订阅下发（Clash/sing-box/base64） |
| **节点与中转** | 多协议多路径、节点健康探活、按吞吐选路、域名池与失联恢复 |
| **支付与收款** | 套餐下单、余额钱包、优惠码、邀请返佣、订单状态机与对账 |
| **后台系统** | 用户/订单/节点/流量/公告管理、运营看板 |
| **工单系统** | 会话式工单、优先级、状态流转、Telegram/邮件通知 |
| **教程与文档** | 分平台客户端教程 + **完整排障体系**（竞品的明显缺口） |

### 5.1 部署形态（硬要求）

**API 与 Web 分开部署。** 这不只是工程洁癖 —— 竞品 conyss 把 SPA 和 `/api/v1/*`
放在同一域名下，一旦该域名被封，用户面板与 API 同时失效。
分离后两者可以有**各自独立的域名池**，互为备份。

## 6 · 非目标（明确不做）

- ❌ **不做公开注册的 to-C 机场生意** — 与「内部使用」定位冲突，且大幅抬高合规与风控成本。
- ❌ **不承诺流媒体解锁**（理由见 §3）。
- ❌ **不做提现** — 钱包余额**仅可消费**，不可提现。这是资金合规底线，竞品同样如此。
- ❌ **不自研客户端**（第一阶段）— 直接对接现役开源客户端
  （Clash Verge Rev / sing-box / Karing / Hiddify / v2rayNG）。
  自研客户端的唯一不可替代价值是**内置域名池自动切换**，留待第二阶段评估。
- ❌ **不引入节点倍率** — 竞品 58 个节点全部 1x。倍率会让用户算不清账，徒增客诉。
- ❌ **不做多租户 SaaS**（不把面板本身卖给别人）。

## 7 · 相对竞品的差异化

竞品弱点已在 [competitor-conyss.md](../01-research/competitor-conyss.md) §6 逐条列出，
本项目取其中**四条可在第一阶段就兑现**的：

| # | 差异点 | 竞品现状 |
|---|---|---|
| 1 | **默认路径用 Hysteria2/QUIC**，单流吞吐 4.6× | 竞品自称 "Shadowcocks"（SS 系），受单流 TCP 拥塞控制约束 |
| 2 | **完整排障文档体系** | 竞品仅 8 篇教程，**零排障文档** |
| 3 | **API/Web 分离 + 双域名池** | 竞品同域部署，一封全封 |
| 4 | **只推现役客户端** | 竞品仍在推已停止维护的 Clash for Windows / ClashX |

另有两条与定价相关（长周期梯度折扣、设备数做档位杠杆），需在 [03-product](../03-product/) 中裁决。

## 8 · 成功指标

因为是内部服务，指标不看增长看**质量与可运维性**：

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 单流下载吞吐（中国 → 全球） | 中位 ≥ 1500 KB/s | 同时段交叉轮询，方法照搬 Proxy_Skill §十一 |
| 主路径可用率 | ≥ 99%（月） | 节点探活，走内核 API 不走系统网络工具 |
| 域名失联恢复时间 | ≤ 30 分钟 | 从检测到封锁至用户可用新域名 |
| 配置类工单占比 | ≤ 20% | 排障文档做得好，这个数字应该很低 |
| 单用户月成本 | 可核算、可覆盖 | 出口流量按 GB 计，对账到套餐定价 |

## 10 · 代价

> ⚠️ 这一选择的代价，必须留在记录里而不是被措辞掩盖：
>
> 1. **选 GCP 做出口 = 放弃流媒体解锁能力**，且 GCP IP 会被持续探测封锁
>    （`vpn-us-ip-v4` 的 `-v4` 证明已换过三次 IP）。换来的是成本可控、
>    与现有资产复用、以及 Premium Tier 骨干的延迟稳定性。
> 2. **「内部使用 + 邀请制」= 放弃规模化营收**。收款体系仍要建（需求明确要求），
>    但其现实定位是成本分摊与账目清晰，不是利润引擎。
>    **若后续要转向公开运营，第 4 节的三条含义全部失效，需要重新裁决合规与风控方案。**
> 3. **复用 `oratis-491316` 而非独立项目 = 接受爆炸半径共享**，
>    详见 [as-built-gcp.md](../02-architecture/as-built-gcp.md) §8。
