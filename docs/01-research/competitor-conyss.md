## 二、域名与抗封锁策略（最值得抄的一点）

访问主域名 `https://conyss.uk` 得到的**不是营销首页**，而是一个纯跳转页：

> 标题：`线路检测页`
> 正文：`线路测试中` / `将自动跳转可用域名 请耐心等候`

即：主域名只承担**域名发现（domain discovery）**职责，前端 JS 依次探测一组备用域名的连通性，
选出第一个可达的跳转过去。实际服务域名形如 `user.conyss01.online`（带序号，暗示 `conyss02` /
`conyss03` … 是预备域名池）。

面板内公告第一条即 **"官网域名（防失联）"**（发布于 2023-06-03，长期置顶），说明域名被墙是
该行业的常态运营问题，而非偶发事故。

**对 babel.plus 的启示**：
1. 入口域名与服务域名必须分离，入口域名是**可牺牲品**。
2. 需要一个域名池 + 客户端/前端侧的自动探测切换逻辑。
3. 需要一个**带外通知渠道**（邮件 / Telegram）在所有域名都失联时推送新域名。
4. 自研客户端的最大价值恰恰在此：客户端可以内置域名池并静默切换，Web 做不到。

## 三、用户面板功能拆解（逐路由）

面板为 hash 路由 SPA，已确认存在的路由：

| 路由 | 功能 |
|---|---|
| `#/dashboard` | 公告轮播 + 我的订阅 + 四个快捷入口 |
| `#/plan` | 套餐选购（按周期 / 按流量 两个 tab） |
| `#/order` | 订单历史 |
| `#/invite` | 邀请返佣 |
| `#/ticket` | 工单 |
| `#/profile` | 个人中心（钱包 / 改密 / 通知 / TG 绑定 / 重置订阅） |
| `#/knowledge` | 教程知识库 |
| `#/node` | 节点列表 |

### 3.1 `#/dashboard` — 仪表盘

- **公告轮播**：4 条，带发布日期，可翻页。内容包括「官网域名（防失联）」「iOS 增强组件」
  「目前已完成四端基础优化，服务正常」「友情推荐：AI账号等自助购买」。
  → 公告既是运维通告渠道，也是**交叉销售位**（推广 AI 账号代购）。
- **我的订阅卡片**：
  - 套餐名：`Lite（小流量用户建议）`
  - `于 2026/09/02 到期，距离到期还有 17 天。已用流量将在 17 日后重置`
  - `已用 3.55 GB / 总计 100.00 GB`
  - → 到期日与流量重置日**绑定为同一天**（订单日），不是自然月 1 号。
- **四个快捷入口**：`查看教程` / `一键订阅` / `续费订阅` / `遇到问题`
  → 这四个正是新用户 → 付费用户 → 留存的关键路径，值得原样保留。

### 3.2 `#/plan` — 套餐（定价情报）

分 **「按周期」** 与 **「按流量」** 两个 tab（后者即流量包）。周期套餐三档：

| 套餐 | 月付价 | 流量/30天 | 设备数 | 峰值带宽 |
|---|---|---|---|---|
| Lite（小流量用户建议） | ¥30.00 | 100 GB | 3 | 500 Mbps |
| Pro（中度用户建议） | ¥60.00 | 230 GB | 3 | 1000 Mbps |
| Ultra（重度用户建议） | ¥90.00 | 400 GB | 3 | 1000 Mbps |

三档共有的卖点文案（逐字）：

- `每月订单日重置流量`
- `BGP内网跨境专线`
- `流媒体解锁`
- `Shadowcocks加密协议`（原文拼写如此）
- `仅支持在中国大陆地区使用`

**定价结构分析**：
- 单价递减：Lite ¥0.30/GB → Pro ¥0.26/GB → Ultra ¥0.225/GB。阶梯很浅，**没有强力的向上销售折扣**。
- 设备数三档统一为 3，未作为差异化杠杆 —— 这是可攻击的差异点。
- 带宽在 Lite 档限速 500Mbps，作为软性区隔。
- `仅支持在中国大陆地区使用` 是一条**合规/风控话术**，把服务定位为「中国大陆出境」单向用途。

### 3.3 `#/order` — 订单历史（商业模式实证）

真实订单流水（节选，跨度 2023-06 → 2026-04）：

| 周期类型 | 金额 | 出现次数 |
|---|---|---|
| 月付 | ¥30.00 | 8 |
| 季付 | ¥90.00 | 6 |
| 半年付 | ¥180.00 | 1 |
| 流量重置包 | ¥23.00 | 6 |
| 流量重置包 | ¥14.00 | 1 |

关键发现：

1. **季付 ¥90 = 月付 ¥30 × 3，半年付 ¥180 = ¥30 × 6 —— 长周期零折扣。**
   这是一个明显的定价失误：用户没有任何理由预付更长周期。babel.plus 应该做梯度折扣
   （如季付 9 折、年付 75 折）来提升 LTV 和现金流。
2. **流量重置包被高频复购**（近半年 7 次），说明 100GB 档位对真实用户偏紧，
   流量包是重要的二次营收来源。价格 ¥23 ≈ 一次重置，另有 ¥14 的档位（可能是小包或促销价）。
3. 订单状态机至少有 `已完成` / `已取消` 两态；列表页操作列有 `查看详情` 与 `取消`。
4. 订单号格式：`2026043023041187363434828`（25 位）
   = `YYYYMMDD`(8) + `HH`(2) + `MM月份`(2) + 13 位随机数。可读性好，便于客服按日期检索。
   → 与 v2board 的 `trade_no` 生成逻辑一致。

### 3.4 `#/node` — 节点列表

**58 个节点，覆盖 30+ 国家/地区**，全部显示 `1 x` 倍率，「订阅计划」列为 `-`（对当前套餐全部开放）。

分布：

| 区域 | 节点 | 数量 |
|---|---|---|
| 🇭🇰 香港 | 香港01–08（其中 07/08 标注「家宽」） | 8 |
| 🇸🇬 新加坡 | 新加坡01–06 | 6 |
| 🇯🇵 日本 | 日本01–06 | 6 |
| 🇺🇸 美国 | 美国01–05 | 5 |
| 🇹🇼 台湾 | 台湾01–03（03 标注「home」） | 3 |
| 亚洲其他 | 泰国、马来西亚、越南、韩国、菲律宾、印度、印尼 | 7 |
| 欧洲 | 英、德、法、爱尔兰、比利时、卢森堡、意、西、葡、希、瑞典、挪威、芬兰、丹麦、冰岛、波兰、瑞士 | 17 |
| 美洲/大洋洲 | 澳大利亚、加拿大、墨西哥、阿根廷、巴西 | 5 |

命名规范极其重要，直接影响用户体验与客服成本：

- 格式：`{国旗emoji}{地区}{两位序号}{(线路类型)}-{解锁能力用丨分隔}`
- 例：`🇭🇰香港07(家宽)-Netflix丨TVB丨Disney+丨OpenAI`
- **节点名即产品说明书**：把「能解锁什么」直接写进节点名，用户在客户端里选节点时无需查文档。
  这是低成本高回报的设计，必须抄。
- `香港01` 的名字被用作**域名广播位**：`🇭🇰香港01 官网:conyss.uk`
  → 节点名是又一个「防失联」触点，因为订阅更新后节点名会同步到客户端。**非常聪明**。
- `(家宽)` / `(home)` 标注住宅 IP 线路，是流媒体/风控敏感场景的溢价卖点。

**倍率全部 1x** 说明其成本结构较均一，或刻意简化用户心智。babel.plus 初期同样建议**不引入倍率**，
避免用户算不清账产生客诉。

### 3.5 `#/invite` — 邀请返佣

| 字段 | 值 |
|---|---|
| 当前剩余佣金 | 0.00 CNY |
| 已注册用户数 | 1 人 |
| 佣金比例 | **10%** |
| 确认中的佣金 | ¥0 |
| 累计获得佣金 | ¥9 |

机制：
- `邀请码管理` — 用户可**自行生成多个邀请码**（列表列：邀请码 / 创建时间）。
- `佣金发放记录` — 列：发放时间 / 佣金（实例：`2026/04/10 17:01  9.00`）。
- `划转` 按钮 — 把佣金划转到账户余额。
- **两段式佣金状态**：`确认中的佣金` → `累计获得佣金`。存在冷静期（防退款套利），设计正确。

`¥9 = ¥90 季付 × 10%`，佣金按订单实付金额计算，非首单限定（待核实是否仅首单）。

### 3.6 `#/profile` — 个人中心

- **我的钱包**：`0.00 CNY`，明确标注 `账户余额(仅消费)` —— **余额不可提现**。
  这是关键的资金合规设计：避免被认定为吸储/支付业务。babel.plus 必须照做。
- **修改密码**：旧密码 + 新密码 + 确认新密码。
- **通知开关**：`到期邮件提醒`、`流量邮件提醒`（两个独立开关）。
- **绑定 Telegram**：`立即开始` —— TG 作为第二通知/客服通道。
- **重置订阅信息**：
  > `当你的订阅地址或账户发生泄漏被他人滥用时，可以在此重置订阅信息。避免带来不必要的损失。`

  → 订阅 URL 携带 token，泄漏即被白嫖。**用户自助重置 token** 是必备功能。

### 3.7 `#/ticket` — 工单

列表字段：`#` / `主题` / `工单级别` / `工单状态` / `创建时间` / `最后回复` / `操作`，
带 `新的工单` 按钮。即标准的 主题 + 优先级 + 状态 + 会话式回复 模型。

### 3.8 `#/knowledge` — 教程知识库

按**平台分类**组织，每个平台恰好 2 篇：一篇第三方客户端 + 一篇自研客户端。

| 平台 | 文章 | 最后更新 |
|---|---|---|
| 苹果手机/iPad | Shadowrocket For Ios 使用教程 | 2026/05/28 |
| 苹果手机/iPad | iOS导入连接增强模块和订阅教程 | 2026/04/27 |
| Android | Clash For Android 使用教程 | 2026/08/08 |
| Android | Android 使用 Conyss 官方客户端（新手适用->推荐) | 2026/06/26 |
| Windows | Clash For Windows 使用教程 | 2026/08/08 |
| Windows | Windows 使用 Conyss 官方客户端（新手适用->推荐） | 2026/06/26 |
| Mac | ClashX For Mac 使用教程 | 2026/08/08 |
| Mac | Mac 使用 Conyss 官方客户端（新手适用->推荐） | 2026/06/26 |

观察：
- 每篇都带 **`最后更新` 日期**，向用户传递「文档是活的」信号，降低不信任感。
- 官方客户端文章统一带 `（新手适用->推荐）` 后缀，做**明确的路径引导**，
  把新手推向可控的自研客户端，减少配置类工单。
- 教程仅 8 篇，**没有故障排查类文档**（订阅更新失败 / 节点全超时 / DNS 泄漏 / 分流规则）。

- 推荐的第三方客户端偏老（Clash for Windows 已停止维护、ClashX 已归档），
  babel.plus 应推荐现役客户端（Clash Verge Rev / mihomo / sing-box / Karing / Hiddify）。

## 四、API 契约情报

抓取到的真实请求：

```
GET https://user.conyss01.online/api/v1/user/order/fetch   →  200
```

这与 **v2board / Xboard 的用户端 API 命名约定完全一致**（`/api/v1/user/{resource}/{action}`，
动作命名为 `fetch` / `save` / `getSubscribe` 等，而非 REST 动词）。

结合路由与页面字段，可高置信推断其用户端 API 面（**待用实际请求逐个核实**）：

| 端点 | 用途 |
|---|---|
| `/api/v1/user/info` | 用户基本信息 |
| `/api/v1/user/getSubscribe` | 订阅链接 + 套餐 + 流量 |
| `/api/v1/user/order/fetch` | ✅ 已实测确认 |
| `/api/v1/user/plan/fetch` | 套餐列表 |
| `/api/v1/user/server/fetch` | 节点列表 |
| `/api/v1/user/invite/fetch` | 邀请与佣金 |
| `/api/v1/user/ticket/fetch` | 工单列表 |
| `/api/v1/user/knowledge/fetch` | 知识库 |
| `/api/v1/user/notice/fetch` | 公告 |
| `/api/v1/user/resetSecurity` | 重置订阅 token |

> 注：以上除 `order/fetch` 外均为基于 v2board 开源约定的推断，标注为 **待核实**。
> 我们不需要兼容它的 API，此处价值在于**印证其技术选型**，从而可直接参考 Xboard 的数据模型。

**重要架构判断**：conyss 的 Web 与 API **同域部署**（`user.conyss01.online` 同时提供 SPA 和
`/api/v1/*`）。这与我们「api 和 web 分开部署」的要求不同 —— 分离部署在抗封锁上更有优势：
Web 静态资源可以放 CDN/多域名，API 域名单独轮换，两者失效互不影响。

## 五、可直接复用的设计（抄）

1. **节点命名即说明书** — `{旗帜}{地区}{序号}{(线路类型)}-{解锁能力}`。
2. **用节点名广播官方域名** — 订阅更新会把域名带进客户端，是最强的防失联触点。
3. **余额「仅消费」不可提现** — 资金合规底线。
4. **订阅 token 用户自助重置** — 防白嫖必备。
5. **佣金两段式（确认中 → 已获得）** — 退款冷静期防套利。
6. **到期/流量双通道提醒开关** + Telegram 绑定。
7. **教程带「最后更新」日期** + 官方客户端标「新手推荐」。
8. **仪表盘四快捷入口** — 教程 / 订阅 / 续费 / 工单，覆盖全生命周期。
9. **公告位兼作交叉销售位**。
10. **流量重置包** 作为周期套餐之外的第二营收曲线。

## 六、可攻击的弱点（超）

| 弱点 | babel.plus 的做法 |
|---|---|
| 长周期零折扣（季付=3×月付） | 做梯度折扣，季 9 折 / 半年 85 折 / 年 75 折，提升 LTV 与现金流 |
| 三档设备数都是 3，无差异化 | 用设备数做档位杠杆（2 / 5 / 10） |
| 教程仅 8 篇，**零排障文档** | 建完整排障体系（订阅失败 / 节点超时 / DNS 泄漏 / 分流 / 流媒体） |
| 推荐已停止维护的客户端（CFW、ClashX） | 只推现役客户端（Clash Verge Rev / sing-box / Karing / Hiddify / v2rayNG） |
| Web 与 API 同域，一封全封 | **API 与 Web 分离部署**，独立域名池，互为备份 |
| 主域名靠 JS 探测跳转，首屏即失败风险 | 域名池 + 客户端内置探测 + 邮件/TG 带外推送三重保险 |
| 面板文案有错别字（"Shadowcocks"） | 基础的专业度即差异化 |
| 无用量可视化（无流量趋势图） | 提供按日流量曲线、按节点用量，提升信任与自助排查能力 |
